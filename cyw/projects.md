## Smart-City-Orch

边缘云平台 Edge-Integrated Microgrid Cloud | 核心全栈开发

Edge-Integrated Cloud Platform 是一套基于 Kubernetes 自研的边缘云操作系统，将多台裸机服务器抽象为统一的资源池，提供节点自动发现、应用编排部署、物理拓扑展示、平台资源监控，多层权限管理等核心能力。平台核心包含自研的编排管理器（Orchestrator），实现对计算节点生命周期、容器化应用调度、持久化存储分配、多租户权限隔离的端到端管控，并集成配置 VPP， DHCP， DNS，openEBS, NFS 等开源组件，支撑编排器对物理节点进行管理。

核心贡献：

1. 框架架构升级（OSGI → Spring Boot）：主导了从遗留 OSGI-Spring 框架到 Spring Boot 4.0.1 + Java 21 的全量架构升级，重新设计模块化工程结构，统一了组件扫描、依赖注入、配置管理和事务控制体系，消除了 OSGI 运行时类加载复杂性，显著降低系统启动延迟并提升团队开发效率。
2. 高可用分布式存储（openEBS + NFS）：引入 openEBS 与 NFS 作为有状态应用的持久化存储方案，为集群提供高可用的分布式块存储能力，以及跨节点访问数据&多节点同时读写能力，为APP的高可用部署提供了基础设施保障。
3. 核心业务开发：负责"集群纳管 → Site 划分 → 镜像上传 → 镜像配置 → 应用部署"全链路的产品化实现。基于 IKubctlClient 抽象实现多 Kubernetes 集群统一管理；站点创建时自动同步 Namespace和节点标签；集成 TUS 断点续传协议对接 Harbor 镜像仓库实现大镜像可靠上传；应用通过参数化模板经 Dispatch 调度引擎翻译为 K8s Deployment / StatefulSet 等资源实现批量编排下发；应用部署时可分配域名，调度K8S创建Ingress资源并同步修改DNS解析记录。


## 交大网管
• > 广播网关 & CIPE 编排管理平台 | 全栈开发 | 2025.12 — 2026.06
  >
  > 与上海交通大学合作，从零构建面向广播网络的编排管理平台，为三类网元提供统一的配置管理、会话监控、软件生命周期与系统运维能力。后端采用 Java 21 + Spring Boot 4.0 Maven 多模块（30+ 子模块），前端 React 18 + MUI + Redux ，数
  > 据库 MySQL，通信层使用 gRPC / HTTP / FTP 多协议，Docker Compose 全容器化部署。
  >
  > - 三端事务一致性：配置变更操作中，通过手动管理数据库事务（autoCommit=false），将数据库持久化、内存快照更新、下游网元全量配置下发纳入同一事务边界——持久化失败或下游返回错误时统一回滚，编排器本地快照也恢复至变更前状态，保证数据、快
  >   照、远端三者最终一致性，杜绝配置漂移。
  >
  > - 实时速率仪表盘：端到端性能优化：下游网元通过 gRPC 流上报会话级性能数据，后端按秒聚合后再广播给前端，避免逐条推送带来的拥塞。前端使用全局发布-订阅 store 集中消费 SSE 数据流——Provider 层建立唯一一条 EventSource 连接，通过
  >   Map<id, Set<callback>> 粒度的订阅分发数据。每个单元格组件利用 React 18 useSyncExternalStore + React.memo 只订阅自己 rowId 的数据变化，SSE 推送一批速率更新时仅触发对应单元格的细粒度 re-render，而非表格整体渲染。相比每个行各自开
  >   SSE 连接，后端长连接数从 O(行数) 降为 O(1)，心跳流量和后端连接资源开销同步降低。全量数据的图表场景（柱状图/折线图）则使用另一套基于 useRef 缓冲 + 定时 flush 的策略，将高频 EventSource 消息批量注入 React 状态。5 秒数据过期自动清理，避免已结束会话的速率残留占坑。
  >
  > - 优化用户体验：实现软件包断点续传上传、批量升级任务编排与进度跟踪，支持升级与回滚；提供配置快照导入导出能力，便于批量部署与灾备恢复；网关重启后自动向网元重建会话，降低人工介入成本；基于 i18next 框架 + CSV 结构化管理中英文翻译文本，运行时无缝切换语言；每个配置编辑操作均带实时校验与三态反馈（编辑中 → 提交中 → 结果），错误时表单保留编辑内容不丢失。
  >
  > - 解耦的分层与模块化架构：后端按 REST 层 → Service 层 → DAO 层分层，每层职责单一、通过接口依赖；同时按业务领域划分为系统配置、gRPC 通信、会话配置、软件管理等独立 Maven 模块，模块间仅通过接口引用，修改一个模块不影响其他。前端则通过组件抽象实现复用——将表格、表单、布局、反馈等模式封装为通用组件，业务面板通过传递不同的列定义、API 端点、校验规则等 Props 快速组合出具体功能，减少重复代码。
  >
  > - 容器化部署：Docker Compose 编排 Nginx + Spring Boot + MySQL 三容器，Webpack 前端构建，一键构建与部署。

## NWDAF

5G NWDAF 实时数据处理系统 | Python / gRPC / 多线程

实时接收 5G NWDAF 推送的每 UE 上行吞吐量数据，通过 AI 模型预测判断网络拥塞状态，并在恢复时自动解除告警，辅助运维人员秒级感知网络异常。后端使用Python + Flask + pandas；模型使用 Isolation Forest 算法；通信使用 gRPC streaming。

* 多线程架构：设计 Router-Worker 分片架构，Router 按 UE_ID 的哈希值分发给固定 Worker，保证时序数据的状态亲和性；Worker 数固定为 CPU 核数，超出负载时执行拒绝策略并记录告警，确保极端情况下系统不崩溃
* 数据回溯：设计结构化日志与 CSV 落盘机制，配合自动化脚本实现数据回溯，模拟消息队列的 offset 重放能力，降低开发调试与模型调优成本
* 后端辅助拥塞判定：基于窗口内历史吞吐量动态计算拥塞阈值，结合多条件状态机（拥塞进入 / 持续拥塞 / 自动恢复）完成网络状态判定，避免 单一 AI 预测结果抖动导致的误判。
* AI 模型自动训练：当目标 UE 模型缺失时自动缓存训练数据，数据量达标后异步线程自动训练 Isolation Forest 模型并落盘，后续推理时按需加载，实现 模型从冷启动到在线推理的无人干预闭环
