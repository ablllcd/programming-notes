# 系统架构设计

> 本文是"架构知识地图 + 书单"的索引，用来搞清楚：架构设计有哪些领域、每个领域解决什么问题、按什么顺序读书。
> 结论先行：**先按"关注点/质量属性"选领域，再按技术栈选书**；三条长期主线是 DDIA（数据与分布式）、DDD 蓝皮书（业务建模）、SAiP（质量属性方法）。

## 一、架构领域怎么划分

### 1.1 企业架构四视图（最常被问的"领域"）

| 视图 | 关注什么 | 典型产物 |
| --- | --- | --- |
| 业务架构 BA | 业务流程、业务能力、组织 | 业务能力地图、价值链、业务流程图 |
| 数据架构 DA | 数据模型、主数据、数据流向、治理 | 领域模型、数据分层、Data Mesh |
| 应用架构 AA | 系统切分、服务边界、集成方式 | 服务清单、调用拓扑、接口契约 |
| 技术架构 TA | 部署形态、中间件选型、非功能指标 | 部署视图、容量模型、SLA/SLO |

这套划分源自 TOGAF / Zachman 一类的企业架构框架（TOGAF ADM、Zachman 矩阵），偏"治理和规划"语境。

### 1.2 按关注点划分（工程实践更好用）

1. 架构基础与决策
2. 架构风格与模式
3. 分布式与数据密集型系统
4. 领域驱动设计与业务建模
5. 微服务与云原生
6. 可靠性与可观测性
7. 性能与容量
8. 安全架构
9. 演进式架构与架构治理
10. 架构文档与沟通
11. 专项：数据/AI、前端、嵌入式/实时

## 二、分领域书单

### 2.1 架构基础与决策（入门第一站）

核心问题：什么是架构、架构风格有哪些、架构决策怎么记录、架构师到底干什么。

- 《软件架构基础》Fundamentals of Software Architecture（Ford & Richards, 2020）——**最合适的"第一本"**，架构风格分类 + 架构决策 + 架构师角色
- 《架构整洁之道》Clean Architecture（Robert C. Martin, 2017）——依赖倒置、边界划分、SOLID 的架构化解读
- 《恰如其分的软件架构》Just Enough Software Architecture——风险驱动，反对过度设计
- 《架构师修炼之道》Design It!（Keeling, 2017）——架构决策与团队协作的实操手册
- 《软件架构实践》Software Architecture in Practice（Bass/Clements/Kazman, 4th ed. 2021）——质量属性场景（QAW）方法论的源头教材

### 2.2 架构风格与模式

核心问题：分层、六边形/端口适配器、整洁、微内核、事件驱动、CQRS、管道-过滤器……各自代价是什么。

- 《企业应用架构模式》Patterns of Enterprise Application Architecture（Fowler, 2002）——分层、领域逻辑、ORM、并发，概念仍通用
- 《企业集成模式》Enterprise Integration Patterns（Hohpe & Woolf, 2003）——消息、路由、转换，集成语汇的事实标准
- POSA 系列 Pattern-Oriented Software Architecture（Vol 1–5）——模式字典，查阅为主
- 《架构师应该知道的 97 件事》97 Things Every Software Architect Should Know——碎片化，适合补盲区
- Software Architecture: Perspectives on an Emerging Discipline（Shaw & Garlan, 1996）——学院派的架构风格起源

### 2.3 分布式与数据密集型系统（技术含量最高）

核心问题：复制、分区、一致性、共识、事务、批处理与流处理、故障模型。

- 《数据密集型应用系统设计》DDIA（Kleppmann, 2017）——**本领域必读第一书**，重点第 5/6/7/9 章
- 《分布式系统：概念与设计》Distributed Systems（Tanenbaum & van Steen）——学院派教材，概念完整，官网有免费 PDF
- Understanding Distributed Systems（Vitillo, 2nd ed.）——工程视角，轻量易读
- 《数据库系统内幕》Database Internals（Petrov, 2019）——存储引擎 + 共识算法（Raft/Paxos）实现细节
- Designing Distributed Systems（Burns）——容器化分布式模式小册子
- 《分布式系统设计原理与范例》/《大规模分布式存储系统》杨传辉——中文体系化读物

### 2.4 领域驱动设计与业务架构

核心问题：复杂业务如何建模、限界上下文怎么切、模型怎么落到代码。

- 《领域驱动设计》Domain-Driven Design（Evans, 2003，蓝皮书）——战略/战术设计原典，难啃但绕不开
- 《领域驱动设计精粹》Domain-Driven Design Distilled（Vernon）——想先尝味道就读它
- 《实现领域驱动设计》Implementing DDD（Vernon, 红皮书）——从模型到代码的桥梁
- Learning Domain-Driven Design（Khononov, 2021）——现代视角，把 DDD 与微服务边界结合得最好
- 《企业级业务架构设计》付晓岩——中文语境下的业务架构方法论

### 2.5 微服务与云原生

核心问题：服务怎么切、跨服务事务与一致性、服务治理、容器编排。

- 《微服务设计》Building Microservices（Newman, 2nd ed. 2021）——最平衡的入门
- 《微服务架构设计模式》Microservices Patterns（Richardson, 2018）——Saga、API 组合、服务发现、事件溯源
- Monolith to Microservices（Newman, 2019）——拆分与迁移策略
- 《云原生模式》Cloud Native Patterns（Davis, 2019）
- Kubernetes Patterns（Ibryam & Huß, 2nd ed.）——K8s 上的架构模式速查
- **《凤凰架构》周志明**——中文里最推荐的分布式 + 云原生体系书，覆盖服务、事务、可观测性，官网免费阅读
- 《大型网站技术架构》李智慧 / 《从零开始学架构》李运华——中文实战向，快速建立全景

### 2.6 可靠性与可观测性（生产视角）

核心问题：故障是常态，如何限流、熔断、降级、发布、定位问题。

- 《发布！设计与部署稳定的分布式系统》Release It!（Nygard, 2nd ed. 2018）——熔断、隔板、超时、稳定性反模式
- 《SRE：Google 运维解密》+ The SRE Workbook + Implementing SRE——SLI/SLO、错误预算、on-call
- Chaos Engineering（Rosenthal & Jones）——混沌工程的体系化
- 《可观测性工程》Observability Engineering（Majors 等）——Metrics / Logs / Traces 与高基数事件

### 2.7 性能与容量

核心问题：延迟与吞吐从哪来、瓶颈如何定位、容量如何规划。

- 《性能之巅》Systems Performance（Brendan Gregg, 2nd ed.）——从 CPU、内存、IO 到应用的整栈方法论
- 《架构即未来》The Art of Scalability + 《架构真经》Scalability Rules——扩展性：组织与技术并重
- Understanding Software Dynamics（Sites）——延迟分析进阶
- Systems Performance 之外的补充：USE 方法（Utilization/Saturation/Errors）值得单独记住

### 2.8 安全架构

核心问题：威胁建模、信任边界、认证授权、密码学工程。

- Security Engineering（Ross Anderson, 3rd ed.）——安全工程百科全书，作者主页免费
- Threat Modeling: Designing for Security（Shostack）——威胁建模四问法
- Zero Trust Networks——零信任架构落地
- 《密码学工程》Cryptography Engineering——需要时再深入

### 2.9 演进式架构与架构治理

核心问题：架构如何随需求演进、如何用机制而非人治守住约束、康威定律怎么用。

- 《演进式架构》Building Evolutionary Architectures（Ford 等, 2nd ed.）——核心概念：适应度函数（fitness function）
- 《团队拓扑》Team Topologies（Skelton & Pais, 2019）——康威定律的现代操作手册，架构 = 组织
- The Software Architect Elevator（Hohpe, 2020）——架构师如何在业务与技术之间上下穿行
- Software Architecture Metrics——用度量替代争论

### 2.10 架构文档与沟通

- 《架构文档化》Documenting Software Architectures（Clements 等）——视图与超越视图
- Documenting Architecture Decisions / ADR（Nygard）——轻量决策记录，实践中性价比极高
- 《程序员修炼之道》《人月神话》《设计原本》（Brooks）——非架构专著，但影响架构思维

### 2.11 专项（按需）

- 数据 / AI：Fundamentals of Data Engineering（Reis & Housley）、Designing Machine Learning Systems（Chip Huyen）、The Data Warehouse Toolkit（Kimball）、Data Mesh（Dehghani）
- 前端：Micro Frontends in Action、Building Micro-Frontends（Mezzalira）
- 嵌入式 / 实时：Making Embedded Systems（White）、Patterns for Time-Triggered Embedded Systems（Pont）
- 换语言看范式：Architecture Patterns with Python（Percival & Gregory）——依赖倒置 + 事件驱动，Java 出身看会有新鲜感

## 三、推荐阅读路线

避免一上来就啃蓝皮书，按"全景 → 硬基础 → 生产与演进"推进：

1. **建立全景（2–3 周）**
   Fundamentals of Software Architecture → 《架构整洁之道》→ 《凤凰架构》
2. **打硬基础（1–2 个月）**
   DDIA（重点 5/6/7/9 章）→ Learning Domain-Driven Design → 《微服务设计》
3. **生产与演进（长期）**
   Release It! → SRE 三本挑一本 → 《演进式架构》+《团队拓扑》
4. **三条长期反复读的主线**
   - DDIA：数据与分布式
   - Evans 蓝皮书：业务建模
   - SAiP：质量属性方法

## 四、选书与实践原则

1. **先"关注点"后"技术栈"**：先确定要解决的质量属性（性能？一致性？可演进？），再挑对应领域的书。
2. **架构 = 权衡**：任何模式都有代价，读书时重点记"这种方案什么时候不适用"。
3. **对着自己的栈反读理论**：本仓库涉及 Spring / JVM / K8s / Kafka / Redis，可以用它们反读 2.3、2.5 两节的理论，避免只学工具不学权衡。
4. **不要按"微服务书单"从头刷到尾**：微服务只是分布式权衡的一个解，不是架构的全部。
5. **输出倒逼输入**：用 ADR（架构决策记录）写下每次选型的原因、备选方案、失效条件——这比读书笔记更能形成架构能力。

## 五、关键概念速查

| 概念 | 一句话解释 |
| --- | --- |
| 质量属性场景 QAW | 把"高性能"翻译成"在 X 条件下，Y 在 Z 时间内完成"，架构才可验证 |
| 适应度函数 | 用自动化测试守住架构约束（如分层依赖、性能阈值） |
| 限界上下文 | 业务模型的边界，通常（但不总是）对应一个服务 |
| 康威定律 | 系统结构会复制组织沟通结构，所以架构调整往往要先调组织 |
| CAP / PACELC | 分区时在一致性与可用性之间取舍；无分区时在延迟与一致性之间取舍 |
| 幂等 / Saga | 分布式事务的工程解法：可重试 + 补偿，而不是两阶段提交 |
| SLI / SLO / 错误预算 | 用可量化的服务目标决定"能不能发版" |
| ADR | Architecture Decision Record，记录一次架构决策的上下文与结论 |
